# 《十四亿分之一》完整更新方案：让选择贯穿一生

- 编制日期：2026-11-23。
- 评估基线：本地现行代码，游戏版本 `2.1.13`。
- 文档性质：待实施的设计与交付方案。本文不表示功能已经实现，也不替代现行 `SPEC.md`。
- 核心约束：轻操作，重人生体验和抉择；剧情预写；保持现有静态技术路线。
- 排序原则：先保证自动生活符合玩家意图，再深化关系与职业，随后补人生变化与回顾，最后扩展内容覆盖。

## 1. 更新目标与边界

### 实施状态（v2.1.7）

- A01：已增加节奏、自动选择、回响与80岁以上人生统计，输出附源码快照哈希及复现元数据。回响统计只衡量可达记录，不替代趣味验收。
- A02：已新增默认关闭的共享钩子，首批覆盖夫妻晚饭、青春期沟通、58岁工作安排。只读取同领域最近手选及已有记忆，失败判定不作为主动意图，无新增必需存档字段。
- A03：已补关键决定的亲选保护、致命风险保护，以及明确丁克后的通用生育排除；40岁生日只在大额买车选项可见时停问。
- 节奏目标尚未完成：保护原先会自动发生的重大决定后，停问增加；本批未找到可安全降级的重大节点。25–35次仍是后续节点合并的目标，不能将本批称为P0全部验收完成。
- 下一步须以逐节点统计合并重复提问，在保留关键选项的前提下降低停问；不通过截断、强行自动选择或隐去风险达标。

本地冻结代码的八组固定策略比较，每组80世：更新前各组平均32.06–38.28次停问，更新后42.60–53.74次；后者P90为49–58次，同年最多3次。因此本批是选择权修复与统计基础，节奏验收不通过，不能直接视为可发布的P0完成版。原始比较与自动选法结果留在被忽略的 `docs/validation/p0-before*.json`、`p0-after*.json`。

本批审查清单保留在 `data/spine.js` 的 `PERSONAL` 常量，普通小事未整体升级。定向验证位于 `tools/check-p0.js`，统计口径验证位于 `tools/check-p0-metrics.js`。

### 1.1 玩家应该感受到的变化

1. 不用频繁点击，小事也大体符合自己已经表现出的处事方式。
2. 当年的选择，会改变多年后遇见的人、获得的机会、承担的责任和相处方式。
3. 不同职业、家庭安排和生活道路，拥有不同的日常与晚年。
4. 年轻时想要的东西可以改变，未完成的愿望也能得到有依据的交代。
5. 结束一世后，能记住两三段属于这个人的经历，并想尝试另一种生活。

### 1.2 必须守住的边界

- 不新增每日任务、打卡、资源收菜、经营排班、反复刷数值等操作。
- 不新增要求玩家管理的性格条、亲密度条、时间点数或跨世战力。
- 不把现实困境一律做成惩罚；代价可以是机会、时间、关系、生活条件，也可以是金钱和健康。
- 不把某种人生设为唯一正解；独身、丁克、普通劳动、返乡和租房都要有完整体验。
- 不把温柔选择一律奖励成大团圆，也不把困难经历解释成玩家选错了。
- 不增加重要选择后的确认步骤；继续保留停钟、2–4个可见选项和明确风险说明。
- 不用新增停问堆内容。优先替换现有普通抉择、深化自动节点、扩展已有文字变体。
- 不接实时AI旁白，不引入新的后端、框架或依赖。
- 不修改既有节点ID、状态键语义、游戏路径和存档前缀。

### 1.3 本轮不纳入

实时经营、股票主动交易、可自由分配的每日时间、伴侣攻略、子女养成面板、跨世属性积累、移民定居，以及新增大量结局数量。

## 2. 现状与证据边界

现有游戏已具备随机出身、教育分流、多行业、经济住房联动、家庭同住、健康疲劳、三年或多年回响、心愿、一次改命、前世残响和结局图鉴。此次升级以深化连接为主。

已确认的主要问题：

本方案尚未经玩家测试。下文的验收目标是拟定门槛，实施前应按第8节建立可复现基线。

## 4. P0：先保证轻操作下的掌控感

### A01：建立节奏与后果基线

**改动内容**

- 在现有比较、模拟工具上补充停问总量、年龄段分布、同年连续停问数、自动选择数、回响兑现数。
- 将后果分别记录为文字变化、生活状态变化、后续入口变化。静态状态键检查只作线索，关键后果必须用设置状态的场景验证。
- 盘点升学、工作、婚姻、住房、育儿、照护、理财、改命各类停问，识别重复确认同一问题的节点。
- 把现有192世结果作为探索记录；正式基线重新记录提交、种子、样本、策略、环境变量和统计口径，不覆盖历史JSON。

**节奏预算**

- 继续以普通完整人生约25–35次主动抉择为设计方向，不对早逝人生强凑数量。
- 研发统计将“普通完整人生”暂定为活到80岁及以上，其他寿命单列；不得通过排除特殊路线掩盖停问过多。
- 平衡样本记录均值、中位数、P90和年龄段；任一策略组停问均值超过35次时，逐项解释并优先合并重复节点。
- 同年连续两次停问进入审查，三次及以上必须调整或写明不可合并的理由；不可为达标自动代选关键决定。
- 不改变1×一年12秒的约定，不靠降低播放速度制造内容分量。

**验收**

形成可复现基线和节点调整清单；后续每个批次都能与相同种子、相同策略比较。

### A02：让自动小事贴合已选经历

**改动内容**

- 优先直接读取职业、家庭和财务相关的既有记忆，不先建立通用性格系统。
- 仅给确有需要的小抉择添加可选的领域和倾向信息。职业求稳、家庭沟通、财务保留余粮分别判断，不用一个“敢冒险”结论覆盖所有领域。
- 玩家最近明确作出的重要决定优先；同一领域有多次经历时，较新的明确选择权重更高。
- 状态不足、互相冲突、选项未标注时，回退现有自动逻辑。
- 自动行为保留适度变化，但不得把明确“不生育、不婚、不借债”等决定解释成可随机推翻的性格偏好。
- 自动消费继续通过现有CN工具，并遵守选项的现金、角色存活和适用条件。

**实现边界**

先检查现有游戏钩子能否承载；确需改共享引擎时，只新增默认关闭、按游戏配置的自动选择钩子。未配置的《江湖一梦》沿用原行为，不改变 `canon/dev` 的原有含义。

不做性格问卷、性格面板或隐形永久人格。新增可选记忆必须注册到SPEC；能从已有记忆推导的内容不重复存储。

**验收**

- 构造“职业求稳、家庭愿意沟通”人物，两个领域的小事分别符合该倾向。
- 后来明确转行后，职业自动行为能随之改变。
- 无历史、旧存档、条件过滤后只剩一个选项时均能正常继续。
- 预览不消耗随机、不改变记忆；一次选择只抽取一次。
- 自动选择不覆盖致命风险、重大消费和不可逆家庭决定。

### A03：划清哪些决定必须亲自选

**改动内容**

- 用“是否明显改变后续生活”审查重大节点，而不是用是否有判定、是否扣属性简单区分。
- 新增或改变职业主路、婚姻、生育、长期住房、照护安排、重大负债和改命机会，原则上必须由玩家亲自决定。
- 已确定决定的执行细节、小额日常支出、重复表态和纯回忆，优先自动发生。
- 行业深分支若要决定十余年的路线，应并入适龄的已有职业停问；不继续把长远路线交给随机自动选择。
- 行业30岁节点需考虑与三十岁关口的重叠。适龄且没有可合并职业节点时，再选择替换较轻停问；不得先新增后补预算。
- 结果文案可简短交代自动行为依据，例如“这些年你一直把手头余粮看得紧，这回也没有追进去”。仅在有意义的变化时出现。

**验收**

提供重大节点保留、合并、转自动的逐项清单；不能因减少停问删掉实际选择权。新旧样本中自动消费、关系变化和路线跳转都有可追溯原因。

## 5. P1：让已有选择真正改变生活

### 第二批实施状态（v2.1.8）

- B01：亲子记忆续接养老商量、照护回响和探望，夫妻记忆续接生日及配偶照护，唯一手足的照护记忆续接生日联系；已检查亡故、多子女、再婚和无法辨认对象时的回退。
- B02试点：饭馆、汽修各三路线，教师、建筑各两路线，共十条路线的40/50岁反馈和79岁晚年活动已接入；实际50岁回响才记录 `career50`，不补造旧档经历。培训费用保持原值，饭馆雇员有独立培训文案。
- B03代表场景：大城租住、小城置业、返乡、父母同住在原46岁住房、52岁父母照护、61岁退休回响中读取，保持原结算和场景工具。
- B04代表场景：更新后连续三年以上的工作、陪伴、锻炼、休息在原十年小结及疲劳回响留下生活痕迹；切换重心或年份缺口重计，不推算旧档过去。
- 本批未新增节点、停问、费用、健康加减或亲密度面板。P0停问预算仍未达标，与本批独立记录；未做真人趣味测试，不宣称已证实更好玩。
- 定向验证：`check-batch2-family.js`、`check-batch2-careers.js`、`check-batch2-life.js`；Chrome桌面/390px三主题真实回响截图：`shot-batch2.js`。

本地验证：简体400世、繁体100世模拟均无问题；十条职业路线与家庭、住房、重心边界测试通过；稀有度按2500世重新生成。与P0相同出生种子的80世“多数人＋默认重心”比较中，平均停问均为50.86次，寿命中位数均为93岁、早逝2.5%、净资产中位数3336672元、事业中位数45、平均完成心愿1.39项；这只证明该组无额外数值或操作变化，不代表所有路线或真人体验。

### B01：家庭记忆贯穿晚年

**改动内容**

- 优先复用 `familyTeen`、`familyWork`、`familyPartner`、`familySibling`、`kidBond`、`kidNoWed` 等已有状态。
- 将具体记忆接入已有探望、配偶生病、养老安排、遗嘱回响等节点，不增加家庭管理面板。
- 人缘保留为广泛社交状态；具体家人的相处方式优先读取该关系的实际经历。
- 每条试点链包含当时的取舍、一次中期反馈、一次晚年兑现。沿用已有节点，避免每条链都增加三段日志。
- 保留修补和改变的可能；主动倾听、各自留空间都可以成为成立的相处方式。

**首批范围**

| 关系 | 接入记忆                                 | 远期表现                                     |
| ---- | ---------------------------------------- | -------------------------------------------- |
| 亲子 | 青春期沟通、第一份工作支持、是否尊重不婚 | 是否愿意谈难处、怎样商量照护、探望时聊什么   |
| 夫妻 | 谈开矛盾、留出个人空间、持续忙碌         | 生病时如何开口、退休后怎样相处、共同回忆什么 |
| 手足 | 照护分担、替班、各管各的                 | 急事时怎样联系、父母离世后是否继续往来       |

**验收**

- 相同人缘、相同同住状态，但家庭记忆不同，至少在两处后续节点读到明确差异。
- 关怀不保证子女顺从；疏远不等于自动失去照护。
- 亡故、离婚、再婚、孩子在外地、独生子女等情况不出现人物串用。
- 首批不承诺完整模拟每个孩子；依照节点实际适用对象读取，不能把长子女经历直接套到所有孩子。
- 经济结算若未来考虑子女支持能力，须单独评估，首批不削减现有晚年接济以制造困难。

### B02：行业路线深化

**改动内容**

- 保留现有行业和30/40/50岁结构，先深化代表职业，再覆盖模板。
- 小生意明确守成、学习升级、少接活三条路的文字与远期结果；不让休息路线继续共用守成经历。
- 服务、农业和建筑行业依据现有两条路线深化，不强行凑成统一三选一。
- 至少一次后续读取改变机会或生活条件，例如接单类型、带徒弟、熟客托付、工作地点或晚年活动。仅加事业、人缘不算完成深化。
- 转行后保留确实积累过的经验，但不自动播放“这些年一直干原职业”的回响。
- 同一职业区分经营者与雇员，复用 `tradeOwn`；培训、工具投资必须符合人物实际身份。

**首批试点**

- 饭馆：熟客经营、团餐升级、缩小接单量。
- 汽修：旧车与口碑、新车型诊断、调整接活节奏。
- 教师：学生支持与教研两条积累，在晚年留下不同关系和活动。
- 建筑：熟练作业与技能转型，体现工作的变化，不重复叠加已有职业疲劳损耗。

首批通过后扩展到其余 `careers-small/service/land` 职业。没有验收的职业不得宣称已完成路线升级。

**验收**

- 每个试点至少两条路线在40岁和50岁有独立反馈，并在之后至少影响一个既有机会、生活状态或晚年节点。
- 小生意休息路线有独立文字，不被写成经营扩张或持续满负荷劳动。
- 对有培训投入的路线检查费用、实际累计收益与失败说明，不保证投入必定回本。
- 不用无依据的额外罚款修平数值；所有经济、健康代价先检查是否已在共享结算发生。

### B03：住房、迁城与照护交叉

**改动内容**

- 将既有城市、住房、同住、返乡和照护状态接入同一事件的变体。
- 优先落在买房后回响、家庭晚饭、父母照护、孩子离家、退休去向等原节点。
- 让房屋体现能否接人同住、是否留有应急钱、住惯的地方和生活边界。
- 通勤与异地奔波先检查已有字段和结算；只有确有状态支持时才写成后果，不用城市等级推断实际通勤分钟数。
- 租房、返乡和不与子女同住都要有成立的生活安排，不统一写成暂时失败。

**验收**

覆盖大城租住、小城置业、返乡、接父母同住四类场景；每类至少与两类家庭或职业节点交叉。地点、收入、住房与像素场景保持一致，无重复房租、照护费或搬迁扣款。

### B04：重心、健康与生活痕迹

**改动内容**

- 继续保留重心的长期手选与阶段默认，不提示玩家逐年优化。
- 在已有年度小结和关键回响里读取重心的持续经历，写出常去的地方、形成的习惯、留给谁的时间。
- 优先从已有记录推导；如无法可靠得出持续年数，只添加最少的本世计数，并明确旧档从何时开始统计。
- 疲劳预警说明当前生活为何撑不住，现有调养、轻岗和硬扛的代价继续保留。
- 改变生活方式后，在已有三年回响和体检中体现恢复与残留影响。
- 休息、陪家人和兴趣不只通向健康或心情，也应留下具体经历；不为每个重心另起任务线。

**验收**

连续工作、长期陪伴、长期锻炼三组在相应节点读到不同生活痕迹。旧档不补造历史，不新增延寿循环，不重复扣工作健康，不为生效要求频繁切换重心。

## 6. P2：让人能够改变，并理解这一生

### C01：心愿变化与人生关口

**改动内容**

- 十六岁仍保留最初志向和三项心愿，作为“当年想要的生活”。
- 优先在三十岁现有关口表达坚持或变化；五十岁关口承接后来的理解，不新开弹框。
- 首版限制最多一次主动调整一个未完成心愿。选项根据经历给出具体方向，最多四个，不出现完整任务池。
- 完成过的心愿保留；旧愿望、后来调整的方向和改变发生的年龄可回看。
- 结算区分如愿、仍惦念和后来放下，不把放下计入完成数，也不通过放下来解锁完成类成就。
- 可调整目标需有前置和合理门槛；不允许临终换入已经满足的愿望凑满完成。
- 家庭关系、健康、职业经历可以改变一个人怎样理解心愿，不自动替玩家放弃它。

**兼容要求**

当前心愿查询依赖志向池。实施时应建立按心愿ID可查询的兼容入口，保留既有ID和 `wishes/wishDone` 原有语义；新增的调整记录使用可选字段。旧档无记录时完整沿用原行为，旧结算不补算。

“实现条件不够”和“因不可逆经历无法再实现”应分开表达；后者给有依据的回顾，不强制换愿望。

**验收**

覆盖坚持原愿、主动改变、已完成后不重置、旧档继续、过期目标、亲人亡故等场景。调整不增加停问、不增加可见选项上限，不抹去原始志向。

### C02：晚年与结算的因果回顾

**改动内容**

- 优先重写现有77岁教育回顾、79岁工作回顾和终局评语，不堆新卡片。
- 从真实选择与记忆中选择2–3段相关经历，讲清当时的决定及后来发生的事。
- 在结算现有记录区域承载回顾，维持人物与结局、主操作、记录和下一世准备的布局层级。
- 职业经历不足时不说“做了一辈子”；回乡不自动等于陪父母，结婚不自动等于和睦。
- 当前按改命和偏离程度挑关键选择的逻辑应兼顾家庭、照护、求稳和放弃机会，避免只有冒险才值得记录。
- 用预写句式和条件组合；有证据才建立因果，只有时间先后时用中性衔接。
- 留言仍优先于临终原话，结局标题和其他结局收录保持原有规则。

**验收**

至少覆盖稳定工作、频繁转行、独身、丁克、离婚、改命失败、早逝、负债和普通长寿。每句话可追溯到记录；资料不足时使用朴素兜底，不编造人物、关系、收入和情感结论。

### C03：改命与前世残响深化

**改动内容**

- 一世一次使用、最多两次邀请的规则不变，不新增改命币或永久奖励。
- 成功、失败、主动留下和现金不足分别写出有依据的后续；不将后两种统一评价为错失人生。
- 改命后的职业经历与B02衔接，失败仍可在后来用到学到的东西，但不偷偷补发必成机会。
- 现有三类前世残响优先深化触发说明和使用后的反馈，暂不扩充种类。
- 结算能交代残响实际用在何处；没用上也有中性说明，不引导反复重开刷取。

**验收**

成功、失败、没钱、主动放弃、未遇到邀请、残响未使用、同命挑战全部可结束。费用和次数不变，残响不叠加、不顺延、不因预览消耗。

### C04：把钱转化成生活余地

**改动内容**

- 保留现有分仓、定投、养老金和行情，不新增投资品类或操作频次。
- 在已有大额支出提示中说明对眼前日子的影响，例如是否动用余粮、是否压缩退休安排。
- 只对有完整数据的场景展示“相当于约几个月结余”；无稳定收入、结余为负或数据不足时，用现金与固定支出描述，不给误导性精确预测。
- 加强给孩子支持、培训、住房和养老资金之间的交叉文字。
- 收益与亏损的后果连接生活选择；不让一次小额支出自动决定整个家庭命运。

**验收**

在富裕、现金紧张、负债和退休四类状态下提示准确，不重复记账，不擅自借债。财务压力不同可以改变感受，但不自动把帮助家人解释成后悔。

**验收：**首批两条旧识链各有初识依据和远期交集；存活、地点、关系均一致，不另增社交停问。

### D03：旅行、宠物、科技与闲笔

- 旅行读取同行者、经济条件和家庭阶段；多年后通过已有照片、回忆或返访文案呼应。

- 闲笔按阶段、所在地和已知经历筛选；优先替换不适用或重复感较强的条目。
- 新生活片段优先占用原年度小结或闲笔位置，控制同年日志长度。

**验收：**旅行有无伴侣、养宠与未养宠、迁居前后、老年照护等场景准确；宠物不复活，亡故人物不同行，科技年代不冲突。

### D04：天赋、图鉴与分享收口

- 天赋优先补独特经历与不同解决方式，不扩张天赋数量和加成。
- 审查明显无代价且处处更优的专属选项；可以保留少量天赋优势，但不能让整条人生路线只有一种合理选择。

- 同命挑战继续只固定起点；如以后展示对照，仅比较实际经历，不判定谁的人生更好。

**验收：**基础与解锁天赋、普通新人生和同命挑战均可用；图鉴不被清档误删，分享不泄露本地私密记录或虚构经历。

## 8. 验证方案

### 8.1 建立可复现的平衡比较

先按现有工具运行固定策略八组、每组80世。再单独运行真实自动选法，检查不同志向的样本量和 `wishByAim`。组别样本不足时补样，不以固定财富志向代替所有志向。

记录寿命、早逝、净资产、事业、学识、心愿、停问数量与年龄分布。自动选择算法变化可能改变随机数消费，配对种子用于比较群体分布，不承诺每个种子后续遭遇完全相同。

```powershell
node 1in1.4b/tools/compare.js 80 1in1.4b/docs/validation/update-plan-baseline.json
```

自动选法使用进程环境变量 `COMPARE_STYLE=auto`；PowerShell以 `try/finally` 保存并恢复原环境值，避免污染后续检查。前后样本均记录准确的代码提交和工具版本。

**通过要求：**没有意外的单一路线全面占优，没有为改善趣味而无依据地增加早逝或压低普通人生收入。明显变化先追因，不按预想数字倒推调参。

### 8.4 浏览器与体验验收

- 使用Chrome或内置浏览器，不使用Edge；使用独立测试存档。
- 检查桌面、390px手机，暗、灰、白主题及键盘操作。

- 拟定一轮5–8名测试者的小规模试玩，观察性结论单列，不把人数换算成普遍满意率。
- 试玩后询问：记住了哪两个决定？后来在哪里看见后果？哪次自动行为不像自己？哪里觉得必须查攻略？

**趣味验收：**测试者能指出实际发生的前后联系；关键问题若集中在自动代选或没看懂代价，先回到P0修正，再扩展内容。

## 9. 交付批次与停止条件

不预先指定新的主次版本号。每次实际发布按系列规则递增补丁号并更新CHANGELOG；未来如需变更前两位，由项目负责人决定。

| 批次                   | 交付范围                           | 进入下一批的条件                                                 |
| ---------------------- | ---------------------------------- | ---------------------------------------------------------------- |
| 第一批：掌控与节奏     | A01–A03                           | 基线完成；自动行为可解释；重大决定不被代选；停问问题有清单与处理 |
| 第二批：关系与工作试点 | B01；B02四个职业；B03、B04代表场景 | 关键链可达；晚年有差异；没有重复费用和健康损耗；试玩看得到后果   |
| 第三批：覆盖现有行业   | B02其余职业；B03、B04补齐          | 所有纳入范围的职业都有独立路线反馈，不用试点代表全部完成         |
| 第四批：人生变化与回顾 | C01–C04                           | 心愿兼容通过；结算可追溯；改命和残响限制保持；分享通过           |
| 第五批：生活差异扩展   | D01–D04                           | 内容覆盖、人物条件、翻译和节奏检查完成                           |

每批都是可独立验收和发布的范围；不等待全部做完才交付。第二批试点若没有改善体验，先调整路线表达，不继续批量复制。

以下情况应缩小或撤回该批改动：

- 新内容导致停问明显增加，却没有更重要的抉择。
- 玩家需要频繁切重心、查最优解或刷新来避免损失。
- 大多数变化只是多几条属性提示，生活与关系没有可见区别。
- 为连接后果而编造历史、复活人物或覆盖玩家明确选择。
- 独身、无子女、普通劳动等路线被系统性写成失败。

## 10. 文件分工与兼容策略

| 位置                                                                         | 主要职责                               |
| ---------------------------------------------------------------------------- | -------------------------------------- |
| `data/world.js`、`game.js`                                               | 人生关口、游戏专属行为钩子、重心入口   |
| `data/spine.js`                                                            | 重大节点、风险提示、回响关联、停问边界 |
| `data/careers-*.js`                                                        | 行业路线、职业条件与远期经历           |
| `data/family.js`、`midlife.js`、`oldage.js`                            | 具体关系、照护和晚年兑现               |
| `data/economy.js`、`finance.js`、`health.js`                           | 既有结算、准确费用和健康边界           |
| `data/fate.js`、`turning.js`、`echo.js`、`legacy.js`                 | 心愿、改命、残响、终局与图鉴           |
| `data/childhood.js`、`travel.js`、`pets.js`、`daily.js`、`tech.js` | 出身、童年和生活细节                   |
| `../../share/engine.js`、`../../share/ui.js`                             | 仅在现有钩子不足时新增通用可选能力     |
| `docs/SPEC.md`、`tools/`、`lang/`                                      | 状态登记、定向验证、翻译与回归         |

兼容规则：

1. 优先读已有状态；新增字段一律可选并有缺失时的行为。
2. 不重命名、删改既有节点ID和状态键，不借新机制重解释旧字段。
3. 新功能原则上只在更新后的经历中自然生效；旧档能可靠读出的历史可使用，不能推断的历史不补造。
4. 保留 `1in1.4b.save.v2` 与 `1in1.4b.album.v1`；若未来确需不兼容迁移，另行制定并审核迁移方案，不在此方案内默认授权。
5. 不重算旧结算的心愿、主结局或分享内容，不清除人生记录和图鉴。
6. 每批更新SPEC中的当前规则、状态键和验收要求，长期规范只记录最终实现。
7. 共享能力默认关闭，以未配置游戏的回归结果证明兼容。

## 11. 完成定义

- [ ] P0–P3工作项均按范围逐项验收；未完成项明确保留，不用整体“已优化”代替。
- [ ] 自动行为更符合已选经历，且没有替玩家作出不可逆重大决定。
- [ ] 行业、家庭和住所能够在后续人生中产生可见区别。
- [ ] 心愿变化保留过去，不制造完成数和成就捷径。
- [ ] 回顾和分享中的经历都能追溯到真实记录。
- [ ] 停问、日志密度和操作量受到预算约束。
- [ ] 没有重复费用、重复健康损耗、虚构历史或人物条件错误。
- [ ] 旧档、图鉴、残响、同命挑战和支持语言经过对应检查。
- [ ] 必要模拟、定向测试、浏览器验收、构建和发布记录完成。
- [ ] 试玩证据与自动检查分开报告；尚未验证的趣味判断不写成已证实结论。
