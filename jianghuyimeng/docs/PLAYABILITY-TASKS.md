# 江湖一梦 · 可玩性任务说明（给编码 Agent）

一次只做一个任务，按编号顺序做。每个任务单独提交、单独升版本号、单独写 CHANGELOG。

## 开工前（每个任务都要）

1. 读仓库根目录 `CLAUDE.md` 和 `jianghuyimeng/docs/SPEC.md`。
2. 读系列规范 GUIDE（`../vibe-game/docs/GUIDE.md`，本地没有就读 CLAUDE.md 里的线上地址）。读不到就停下问用户。
3. 跑一次基线，记下输出：`node share/tools/simulate.js jianghuyimeng 40`（现在是“没有发现问题”）。

## 通用约束

- 剧情文字只放 `jianghuyimeng/data/*.js`，游戏专属逻辑放 `jianghuyimeng/` 下。**不在 `share/` 里写江湖一梦专属的字、人名、颜色。**
- `share/engine.js` 的 `g` 接口和数据格式只能加，不能改、不能删。能用现有钩子就不动 `share/`。
- 不改存档结构（`W`、`L`）。要长期保存的新数据用单独的键（见任务 2）。
- 不改江湖纪年表、不改已有改命标记的名字、不改 `game.js` 的字段名。
- 新增数据文件要加进 `jianghuyimeng/index.html` 的 `<script>` 列表（放在 `data/encounters.js` 之后、`JY.loadLangData()` 之前）。
- 文风、选项数（2–4）、后果规则、人物关系（`g.knows`）照 SPEC。
- 现有可参考的实现：`1in1.4b/data/legacy.js`（`onFinish`、`endCards`、`homeCards`、图鉴存储）、`1in1.4b/data/spine.js`（`engine.minor`、`echoOf`）。照它的做法，不要照抄它的内容。

## 任务 1：每个可玩人物 3 个“心愿”

**目标**：开局告诉玩家这一世可以争取什么，命终时打勾。

**现状**：12 个可玩人物，玩家只看到 `fateText`（原著命数）和一个改命度百分比，没有目标。

**做法**

- 新文件 `jianghuyimeng/data/wishes.js`，注册 `JY.WISHES = { <人物id>: [ { id, t, done: (g, life) => 布尔 }, ... ] }`。每人 3 条。
- `done` 只读已有的东西：`g.f('标记')`、`g.alive('id')`、`g.s('属性')`、`g.recall('键')`、`life.to - life.born`（享年）、`life.cause`。读标记写成字面的 `g.f('名字')`。
- 三条的难度分开：一条照原著也能成，一条要改一次命，一条要连着做对几件事。
- 在 `game.js` 用 `engine.onFinish(g, life)` 算出 `life.wishes = [{ t, ok }]`。
- 用 `GAME.endCards(life, u)` 在墓志页加一张“这一世的心愿”卡，列三条，达成的打勾。
- 用 `GAME.share.badges(life)` 在分享卡上加一行“心愿 2/3”。
- 醒来页和名帖要能看到这三条。先看 `share/ui.js` 有没有现成的位置（例如名帖字段用 `g.info('心愿', ...)`）；没有就在 `share/ui.js` 加一个**通用的可选钩子**，不写死任何文字。

**心愿示例**（写法参考，内容由你按原著和现有标记定）

- 杨康：活过纪年 19；认回杨铁心；亲手带大杨过。
- 郭芙：没有砍断杨过的手臂；活过襄阳城破；嫁给自己选的人。

**验收**

- 12 个人物各 3 条，每条在 simulate 的 40 轮里至少有一次达成、至少有一次没达成（写一段临时脚本统计，结果贴在交付说明里）。
- 没有“永远达成”或“永远达不成”的心愿。
- 墓志页、分享卡、醒来页三处都能看到。

## 任务 2：结局图鉴和改命图鉴

**目标**：首页显示收集进度，让人想再来一世。

**做法**

- 新文件 `jianghuyimeng/data/legacy.js`。
- **结局**：每个可玩人物 4–8 个有名字的结局，写成 `{ id, t, d, when: (g, life) => 布尔 }`，从上到下第一个命中的算数，最后一条是兜底（“照着书里过完”）。按已有标记和死法判定，不新写剧情。
- **图鉴存储**：单独的键 `jianghuyimeng.album.v1`（做法同 `1in1.4b.album.v1`），“重开一个江湖”不清它。存：见过的结局 id、设过的改命标记名、达成过的心愿 id、活过几世。键名先对照 GUIDE 的存档键规则，冲突就按 GUIDE。
- `onFinish` 里算出 `life.end`，更新图鉴，把这一世新收集到的东西记在 `life.fresh`。
- `endCards`：显示结局名和一句说明；有新收集就列出来。
- `homeCards(W, u)`：首页一块“江湖图鉴”，显示“结局 x / 总数”“改过的事 x / 总数”“心愿 x / 36”，按人物分行。没见过的结局只显示“？？？”，不剧透。
- 改命总数按 `JY.addFlags` 注册的数量算（现在约 172 个）。只算玩家这一世亲手设的（`life.changes`），不算前世留下的。

**验收**

- 每个人物的每个结局在 simulate 里至少出现一次；只靠前世标记才能到的结局要在交付说明里列出来，并单独设标记测一次。
- 重开一个江湖后图鉴还在。
- 首页图鉴在 390px 宽下不横向滚动。

## 任务 3：空白年缩短

**目标**：没有任何事的年份过得快一点，有内容的年份保持原速。

**已定（用户确认，不要改）**

- 1× 仍是一年 60 秒，不加 `yearMs`。
- 所有抉择都停下问玩家，**不加 `engine.minor`**，不做自动选。
- 只缩短空白年：1× 下走 20 秒。

**现状**：抉择集中在 10–30 岁，郭靖 40–59 岁没有抉择，最大空档 22 年。每年生平字数中位 58 字、九成年份在 134 字以内，空白年只有一两句闲笔，60 秒里大半在等。

**做法**

- `jianghuyimeng/game.js` 加一个可选字段 `quietYearMs: 20000`。
- `share/ui.js` 的 `yearMs()` 读它：这一年是空白年就用 `quietYearMs / 速度`，否则照旧。没写这个字段的游戏行为完全不变（十四亿分之一不受影响）。这是通用的可选钩子，`share/` 里不写任何江湖一梦专属的东西。
- **空白年的定义**：这一年推演完之后，生平里只有闲笔和年度重心的那几行。出现下面任何一样就不算空白年：
  - 本人的剧情节点（自动的、抉择的都算）
  - 奇遇、回响、人生关口
  - 世界事件（江湖传闻）
  - 练功的境界、内伤、走火入魔
  - 身边的人去世
  - 命终那一年
- 先看 `share/engine.js` 里 `G.log(文字, 种类)` 现在用了哪些种类名，按种类判断；判断不出来的行按“有事”处理，宁可不缩短。
- 空白年的文字仍在前 85% 的时间里均匀出现，进度条照样从头走到尾。
- 速度倍数照常叠加（2× 时空白年 10 秒）。顶栏那行“1× · 一年约 1 分钟”不改。
- 更新 CLAUDE.md“用户偏好”和 SPEC 里讲节奏的地方，各加一句说明空白年 20 秒。

**验收**

- 写一段临时脚本，统计每个人物一生里空白年占几成、1× 下一生总时长改前改后各多少分钟。结果贴在交付说明里。
- 抽查 20 个被判成空白的年份，把那年的生平贴出来，确认里面没有上面列的任何一样。
- 空白年的字数最多的那一年，按每秒 6 个字算，17 秒内读得完；读不完就把那类行改判成“有事”。
- `node share/tools/simulate.js 1in1.4b 40` 仍然“没有发现问题”，`SHOT_WAIT=20000` 的 `-run` 截图在十四亿分之一上走过的年数和改之前一样。

## 任务 4：补中晚年的专属节点

**目标**：45 岁以后还是“这个人”的故事。

**现状**：45 岁后主要靠通用的 `e_late_*`，按规定不提原著人物。各人物抉择按十年的分布（十几岁最多）：

| 人物 | 40 岁后的抉择数 | 最大空档（年） |
|---|---|---|
| 郭靖 | 4（都在 60 岁后） | 22 |
| 穆念慈 | 1 | 21 |
| 赵敏 | 2 | 16 |
| 黄蓉 | 4 | 15 |
| 杨过 | 5 | 15 |
| 张无忌 | 2 | 15 |

**做法**

- 先做上表六个人，每人加 4–6 个节点（至少 3 个是抉择），填在最大空档里。其余六人各加 2–3 个。
- 内容来自原著里这个人这段年纪该有的事，以及这一世前面改命的后果（读 `g.f`、`g.recall`）。例：郭靖四十多岁守襄阳、教郭破虏、和杨过的关系。
- 每个新抉择至少一个 `canon`、一个带 `dev` 的改命选项，至少 2 个选项有读得到的后果。
- 原著里这个人这时已经死了的（杨康、穆念慈、李莫愁），节点要带 `cond`，只在改命活下来时出现。这类节点随机测试可能碰不到，要单独设标记测。
- 节点 id 全局唯一。提到别人先 `g.alive`、`g.knows`。

**验收**

- simulate 清零，新抉择都触发过（靠前世标记的除外，列出来并单独测过）。
- 上表六个人的最大空档都降到 10 年以内。

## 任务 5：年度重心有的放矢

**目标**：玩家知道现在练什么是为了后面哪件事。

**现状**：重心只是每年加一两点属性。判定公式是 `50 + (属性 − 门槛) × 3`，但玩家事先不知道后面要考什么。弹框支持节点的 `stake` 和选项的 `hint`，江湖一梦没用。

**做法**

- 给带 `check` 的重要抉择（每人 5–8 个）写 `stake`：一句话说这件事的分量。
- 给带 `check` 的选项写 `hint`：这一步靠什么（“看武学”“看悟性，越高越稳”）。先看 `share/ui.js` 现在怎么显示成功率，别重复。
- “今年的重心”卡上加一行**预告**：未来 5 年内本人最近的一个带判定的原著节点，写成“三年后有一场硬仗，看武学”。只说年头和属性，不剧透内容。实现成 `game.js` 里的函数；`share/ui.js` 没有显示位置就加一个通用的可选钩子。
- 预告只算此刻 `cond` 成立的节点。

**验收**

- 截图 `-menu`、`-jump` 剧本，桌面和手机都看得到预告，手机的 `focusBar` 仍是两行、不横向滚动。
- 没有带判定节点的年份不显示预告。

## 任务 6：把跨世改命摆到台面上

**目标**：让玩家看见“上一世做的事，这一世还在”。这是这个游戏独有的卖点。

**做法**

- **生平标记**：因为前世留下的标记而变了的文字，行尾加一个小标记“前世所改”。实现上：节点或世界事件在求值时读到了“不是这一世设的”标记就算。优先在 `g.f` 上做一个不改语义的记录（只加，不改返回值），界面按记录加样式。动 `share/engine.js` 要对两个游戏都跑 simulate。
- **首页世界线**：在首页用 `homeCards` 加一块“这个江湖已经不一样了”，列出本江湖已设的标记说明（`JY.addFlags` 的说明文字）和是哪一世改的。
- **选人时提示**：可选人物卡上加一行“这一世会和书里不同：N 处”，N 是这个人的节点里读到已设标记的个数。
- **跨世任务**：新文件 `jianghuyimeng/data/quests.js`，5–8 个要两世以上才能完成的目标，写成 `{ id, t, d, done: (W) => 布尔 }`，只读 `W.flags` 和 `W.lives`。例：“先做郭芙，再做杨过：杨过双臂俱全，小龙女没有跳崖”。完成的记进任务 2 的图鉴。

**验收**

- 用两世的脚本测一遍：第一世设标记，第二世的生平里出现“前世所改”，首页世界线列出这件事。
- 每个跨世任务都有一段可复现的测试路径，写在交付说明里。
- 1in1.4b 的 simulate 仍然清零，界面没有多出任何东西。

## 任务 9：加险境

**目标**：让改命有代价。

**现状**：每人致命选项 0–2 个，穆念慈、小龙女、张无忌、赵敏、周芷若一个都没有。

**做法**

- 每人加到 2–3 个高风险选项，加在已有抉择上，不新开节点。写 `check`，成功给大的改命（`dev` 30–50）和读得到的后果；`fail` 里重伤（`g.remember('ns', ...)` 加内伤）或死（`fatal: true`，`g.die('死法')`）。
- 弹框里要看得出这一步会出人命（先看 `share/ui.js` 现在怎么标 `fatal`，不够明显就用 `hint`）。
- 不写虐杀细节，死亡一句话带过。

**验收**

- simulate 清零，平均寿命和基线比下降不超过 5 岁（把前后两次的平均寿命贴出来）。
- 自动选（`E.autoIndex`）不会选到致命选项，引擎已有这条，确认没被绕过。
